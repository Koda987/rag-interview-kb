Q: 一个好 prompt 通常包含哪些要素？
A: 四要素：角色（你是资深后端工程师）、任务（审查这段代码）、约束（只指出安全问题，逐条列出）、格式（用 markdown 表格输出）。再加几个示例（few-shot）和输出长度控制会更稳。要素越明确，模型自由发挥的空间越小，输出越可控。

Q: few-shot prompting 是什么？
A: 在 prompt 里放几个"输入→输出"的示例让模型模仿。模型天生擅长模式延续，给两三个例子往往比长篇文字描述更有效。注意示例要覆盖边界情况、格式完全一致——模型会把示例里的错误格式也一起模仿掉。

Q: 什么是思维链（Chain-of-Thought）？
A: 让模型"先写推理过程再给答案"，多步推理任务（数学、逻辑题）准确率显著提升——因为每个 token 的生成都能参考前面展开的中间步骤，相当于给了模型草稿纸。零样本版只需一句"让我们一步一步思考"。代价是 token 消耗变大。

Q: 怎么让模型稳定输出 JSON 等结构化格式？
A: 三层保险：prompt 里给出明确的 JSON schema 和示例；调用支持 JSON mode 的接口强制格式；代码侧永远做解析校验加失败重试。不要指望一次就完美——解析失败是常态，重试与降级策略必须提前设计。

Q: function calling 的原理是什么？
A: 开发者预先声明可用函数的名字、参数和用途（JSON schema）。模型读到用户请求后不直接回答，而是输出"应该调用哪个函数加参数"；真正执行由你的代码完成，结果再喂回模型生成最终回答。模型只做决策不做执行——它是大脑，你的代码是手脚。

Q: ReAct 循环是怎么工作的？
A: Agent 的经典执行模式：Thought（思考该做什么）→ Action（调用工具）→ Observation（观察工具返回）循环往复，直到 Thought 判断可以给出最终答案。把推理和行动交织，模型能根据中间结果调整下一步——这是 Agent 区别于单轮调用的核心。

Q: Agent 的记忆一般怎么设计？
A: 短期记忆：当前对话上下文，超长就截断或摘要。长期记忆：把重要信息向量化存库，需要时检索回来——本质是对自己的历史做 RAG。工程要点是控制 token 预算：什么该记、什么该压缩、什么该忘，比"记多少"更关键。

Q: MCP 是什么？
A: Model Context Protocol，Anthropic 推出的开放协议，统一"模型如何连接外部工具和数据源"的接口标准。类比 USB 接口：工具方实现一次 MCP server，任何支持 MCP 的模型客户端都能即插即用，不用为每个模型单独写适配层。

Q: 多轮对话怎么控制 token 成本？
A: 手段按代价从低到高：截断旧历史；把历史摘要压缩；只保留最近几轮加系统提示；检索式记忆按需调回。注意 system prompt 每轮都重复计费，RAG 引用块也只取 Top-K 最相关的——上下文里的每个 token 都是钱。
