Q: SSE 和 WebSocket 有什么区别？
A: SSE：服务器单向推送，基于普通 HTTP，自带断线重连，实现简单——对话流式输出够用。WebSocket：全双工双向，独立协议，适合客户端也要主动发消息的场景（游戏、协同编辑）。LLM 应用逐字吐词是典型单向流，SSE 是性价比之选，主流大模型 API 都用它。

Q: SSE 流式响应的帧格式是什么？
A: 每帧以 data: 开头，帧与帧之间用空行分隔。实践中要把文本包进 JSON（如 data: {"text": "..."}）再发送——否则文本自带的换行会把一帧拆成两帧，客户端解析就乱了。流的结尾发 data: [DONE] 哨兵标记结束。

Q: async/await 和事件循环是怎么回事？
A: async 函数是单线程协作式多任务：遇到 await 就让出线程给别人跑，结果回来再继续——像餐厅一个服务员同时照看多桌，哪桌上菜了去哪桌，而不是每桌配一个服务员站岗。适合网络 IO 密集场景；CPU 密集任务它无能为力，那要用多进程。

Q: Django 里 async 视图为什么不能直接查 ORM？
A: Django ORM 的连接管理默认假设同步环境，在事件循环线程里直接查询会抛 SynchronousOnlyOperation。两条出路：视图就用普通 def（Django 自动丢线程池执行）；或用 sync_to_async / run_in_threadpool 把 ORM 调用显式包起来。这类异常若被 except 静默吞掉，极难排查。

Q: RESTful API 设计的要点是什么？
A: 资源用名词复数（/documents），动作用 HTTP 方法表达（GET 读、POST 建、PUT/PATCH 改、DELETE 删），状态码语义化（404 不存在、401 未认证、422 参数错）。无状态：每个请求自带全部上下文，服务器不记会话——这是水平扩展的前提。

Q: CORS 是什么？怎么解决？
A: 浏览器的同源策略会限制页面请求不同源的后端接口，后端需要响应 Access-Control-Allow-Origin 头放行。常见坑：允许所有来源（*）与允许携带凭证（credentials）不能同时开启——浏览器会直接拒绝，这是 CORS 中间件最常见的配置错误。

Q: API 密钥管理的正确姿势是什么？
A: 铁律：密钥只放环境变量或密钥管理服务，代码和仓库里绝不出现——一旦提交进 git 历史，事后删除也没用，历史里还在。.gitignore 排除 .env 类文件；不同服务用不同密钥，便于轮换和定位泄露；疑似泄露第一时间吊销，而不是只删代码。

Q: 什么是幂等性？为什么重要？
A: 同一请求重复执行，效果和执行一次相同。GET/PUT/DELETE 天然幂等，POST 不是——重复点击"支付"绝不能扣两次钱。手段：客户端生成唯一请求 ID，服务端去重。网络抖动下重试很常见，重试机制只有配上幂等才安全，否则重试就是放大事故。

Q: 为什么 LLM 应用都要做流式输出？
A: 生成一段完整回答要几秒到几十秒，等全部生成完再返回，用户面对白屏会以为程序死了。流式把生成的第一个字在几百毫秒内推给用户，体感速度提升一个数量级——首 token 延迟（TTFT）是 LLM 应用的核心体验指标，比总耗时更影响感受。
